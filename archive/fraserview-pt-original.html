Critique · Oct 7–8 · Figma comments

Small changes, real facts.

We left feedback on each other’s frames with Figma comments. The layouts held up, so the second round was about two things: balance and truth.

Type balance

The contrast between headline and body sizes was too strong. We brought the sizes closer so the text reads as one voice.

Real copy, not placeholder

Temporary body copy from the mockup stage was replaced with facts from the shop’s real data: review count, rating, address and drop-off times.

4.7 from 21,000 reviews
→
5.0 from 226 reviews

Home: the best of each option

We compared hero, package and location options and kept one of each: Hero A, Packages A, Location A.

Handoff

Ready for
developers.

We followed the five-item checklist. Developers will build this with AI, so we checked that our notes come through Figma MCP.

01

Clear names

Page / Step / Size, e.g. Booking / Step 2 Date and time / Mobile. No default layer names.

02

Key flows prototyped

Six named flows: Home and Services on desktop and mobile, plus the empty and error states.

03

Starting points

Each flow starts at Home, Services, or its own state screen.

04

Styles, components, variables

Every colour is a variable, every text has a style. Selected, Fully booked and Error are component variants.

05

Notes for developers

17 Dev Mode annotations, tagged Interaction, Form, Business rule, Responsive and Accessibility.

Interaction · BackGoing back keeps all choices and typed values.
Business rule · CalendarWeekday evenings, every 15 minutes, 6:30–9:45 pm. Past days and weekends are unavailable.
Form · EmailOn Confirm, focus moves to the first error: “Enter an email like name@example.com.”
Interaction · ConfirmWhile sending, show “Booking…” and disable the button. If the time was just taken, go back to Step 2.
Responsive · HeaderHide “Book Now” in the header during Steps 1–3.
Accessibility · MarqueePauses on hover or focus. With reduced motion, a static grid.

Breakpoints

  • Designed at 1440 and 390.
  • Below 768px: mobile layout.
  • Tune cards: 1 column, 2×2 from 768px, 4 in a row from 1200px.

Accessibility

  • Text meets 4.5:1; input borders 3:1.
  • Alt text on photos; duplicate marquee logos are aria-hidden.
  • Keyboard support for radios, calendar and stepper.

Open questions

  • Keep YouCanBookMe or build our own booking backend?
  • Who sends the confirmation email?
  • Postal code differs between the site and Google.

Looking back

A developer and a designer, one goal.

Two people on the same line, looking from opposite sides. There was no product manager between us, so we shared that role.

🤯

Struggles

Different starting points. YJ, a branding and visual designer, put beauty first. Tak, a developer, worked from facts and data. With no PM in the middle, every priority call was ours to make together.

🏆

Achievements

User experience became our shared goal and our bridge. One design system, 3 pages, 6 prototype flows and a full developer handoff in 9 days.

🌱

Improvements

We did not run user testing this time. Next time we would test the current site with real riders before wireframing.

👩‍🎨

YJ · designer

I learned to design for the developer as well as the user, and to put the experience before the look.
